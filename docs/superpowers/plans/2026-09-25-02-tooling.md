# Tooling (cluster 02) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, `bash tools/regenerate.sh`, writes every generated copy in the repository, and CI proves the committed tree equals its output.

**Architecture:** A bash entry point calls ready-made tools in a fixed order: `jq` for the catalogue and the README table, byte copies for LICENSE and the vendor manifest, `sed` for the install template, `awk` for region replacement and front-matter stripping, doctoc, pinned with its whole dependency tree by `tools/package-lock.json`, for tables of contents. Generated text inside hand-written files sits between `<!-- NAME:start -->` / `<!-- NAME:end -->` lines. The vendor manifest `plugins/<name>/.claude-plugin/plugin.json` changes from a symlink to a byte-identical copy, and `tools/check-conformance.py` checks byte equality instead of symlink targets.

**Tech Stack:** bash (3.2 or later; macOS `/bin/bash` 3.2.57 ran it), jq 1.7, awk, sed, doctoc 2.2.1 installed by `npm ci` from `tools/package-lock.json` on Node 22, Python 3.12 with `jsonschema` and `pyyaml` for the check, GitHub Actions.

## Contract for plans 03–07

Plans 03–06 consume this contract and do not edit the script. A plan that needs a change says so, and the change comes back here.

**Region markers.** A region is two whole lines, exactly `<!-- NAME:start -->` and `<!-- NAME:end -->`, no leading or trailing spaces. To add a region, write the two lines next to each other and run `bash tools/regenerate.sh`.

**Region semantics** (`replace_region FILE REGION CONTENT`):

| State of FILE | Result |
| :-- | :-- |
| FILE does not exist | skipped, no output, exit 0 |
| neither marker line present | skipped, no change, exit 0 |
| exactly one start line and one end line, start first | lines between them replaced |
| start without end, end without start, or either line twice | exit 1: `regenerate: FILE: region 'NAME' needs one '<!-- NAME:start -->' line and one '<!-- NAME:end -->' line; found S and E` |
| end line before start line | exit 1: `regenerate: FILE: '<!-- NAME:end -->' comes before '<!-- NAME:start -->'` |

The replaced text is: one blank line, the content with blank lines trimmed from both ends, one blank line. An empty content leaves one blank line between the markers. The blank lines keep a table or a paragraph from running into an HTML comment line.

**Regions the script fills** (names and files as the conventions fix them):

| Region | File | Content |
| :-- | :-- | :-- |
| `plugins` | `README.md` | `\| Plugin \| What it does \|`, `\| :-- \| :-- \|`, then one row per `plugins/*/plugin.json` sorted by `name`: `\| [<name>](plugins/<dir>/README.md) \| <description, with \| escaped> \|` |
| `description` | `plugins/<dir>/README.md` | `jq -r .description plugins/<dir>/plugin.json`, one paragraph |
| `install` | `plugins/<dir>/README.md` | `tools/templates/install.md` with `{{name}}` → the manifest `name` |
| `hosts` | `plugins/<dir>/README.md` | one line `` - `<host>` `` per entry of `extensions["io.github.akurganow.ai-plugins"].network.hosts`, in the manifest's order; a manifest without that key leaves the region untouched, markers or not |
| `install` | `README.md` | the same template with `{{name}}` → `<name>` |
| `rules` | `plugins/prose-discipline/skills/house-style/SKILL.md` | `plugins/prose-discipline/rules/prose-discipline.md` without its leading `---` … `---` block |
| `hermes-auto-load` | `plugins/prose-discipline/README.md` | a fenced `yaml` block: `skills:` / `  auto_load:` / `    - agent-plugin-prose-discipline-cf518319:house-style` |

The install template's client headings are `###`. Plans 04–06 put the `install` markers under an `## Install` heading.

**Whole-file copies** (no markers): `plugins/<dir>/LICENSE` from `LICENSE`; `plugins/<dir>/.claude-plugin/plugin.json` from `plugins/<dir>/plugin.json`, replacing a symlink if one is there; `.claude-plugin/marketplace.json` from the template plus one entry per manifest.

**Catalogue entry:** `{name, source: "./plugins/<dir>", description, homepage, category}`, `category` read from `extensions["io.github.akurganow.ai-plugins"].category`, entries sorted by `name`. A key whose manifest value is absent is left out rather than written as `null`. Until plans 03–05 add `category`, entries carry no `category` key.

**Tables of contents:** `tools/node_modules/.bin/doctoc --github --notitle`, installed by `npm ci --prefix tools --no-audit --no-fund` when that binary is absent, runs over every `*.md` file found by `find plugins/*/skills/*/references -type f -name '*.md'` that is longer than 100 lines or already holds a `<!-- START doctoc ` line, except `plugins/howp/skills/*/references/commands.md`. The pattern is a glob, so the skill renames in plans 03–05 need no script change. doctoc puts the TOC at the very top of the file, above the H1, between its own `<!-- START doctoc … -->` / `<!-- END doctoc … -->` lines. `--notitle` drops doctoc's default title, which links to doctoc itself. A plan that edits a reference runs the generator afterwards; CI fails otherwise.

**Root README table of contents:** when `README.md` holds a line starting `<!-- START doctoc `, the same binary runs with `--maxlevel 2` over `README.md`, after the README regions are filled. Without that line the README gets no TOC. Plan 06 adds doctoc's two full marker lines, `<!-- START doctoc generated TOC please keep comment here to allow auto update -->` and `<!-- END doctoc generated TOC please keep comment here to allow auto update -->`, where the TOC belongs; doctoc lists only the headings below its end marker.

**Hermes qualified name:** `agent-plugin-<slug>-<first 8 hex of sha256(name)>:house-style`, where `slug` is `name` lowercased, with every character outside `[a-z0-9_-]` replaced by `-` and leading and trailing `-`/`_` stripped. For `prose-discipline` the output is `agent-plugin-prose-discipline-cf518319:house-style`.

**CI:** `bash tools/regenerate.sh`, then `git add --intent-to-add --all`, then `git diff --exit-code`; failure prints `Generated files differ from their sources. Run bash tools/regenerate.sh and commit the result.` The `--intent-to-add` line departs from the bare `git diff --exit-code` in the conventions. Without it, a copy missing from the commit (a deleted `LICENSE`, say) comes back untracked and passes.

**Interim state.** After this plan lands, three texts describe the old symlink until their own plans change them: `README.md` "Cloning on Windows" and "Layout" (plan 06), and `.agents/rules/conformance.md` "Package shape" bullet 1 (plan 01).

- [ ] **Step 5: Write `tools/regenerate.sh`**

````bash
#!/usr/bin/env bash
# Regenerates every file in this repository that is a copy of another.
#
# Each generated file has one source, named in the step that writes it. CI
# runs this script and then fails when the tree differs from the commit, so
# a copy edited by hand, or a source edited without running this, does not
# merge. A second run changes nothing.
#
# A generated region inside a hand-written file sits between two lines,
# `<!-- NAME:start -->` and `<!-- NAME:end -->`. A file without the start
# line is skipped, so a region takes effect once someone adds its markers.
set -euo pipefail

die() {
  printf 'regenerate: %s\n' "$*" >&2
  exit 1
}

[ "$#" -eq 0 ] || die "takes no arguments"

for tool in jq node npm awk sed grep find sort wc cut tr cmp cat mktemp dirname; do
  command -v "$tool" >/dev/null 2>&1 || die "$tool is not installed"
done
if command -v shasum >/dev/null 2>&1; then
  sha256() { shasum -a 256; }
elif command -v sha256sum >/dev/null 2>&1; then
  sha256() { sha256sum; }
else
  die "shasum is not installed, and neither is sha256sum"
fi

cd "$(dirname "$0")/.."

WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT

# write_if_changed SOURCE DEST: copy SOURCE over DEST unless they are equal.
# `cat >` keeps DEST's mode; a symlink at DEST is removed first, so the copy
# lands at DEST and not at the link's target.
write_if_changed() {
  if [ -L "$2" ]; then
    rm "$2"
  elif cmp -s "$1" "$2"; then
    return 0
  fi
  cat "$1" >"$2"
}

# replace_region FILE REGION CONTENT: put the lines of CONTENT between the
# REGION markers in FILE, trimmed of blank lines at both ends, with one blank
# line after the start marker and one before the end marker.
replace_region() {
  local file=$1 region=$2 content=$3
  local start="<!-- ${region}:start -->" end="<!-- ${region}:end -->"
  local starts ends out="$WORK/region"
  [ -f "$file" ] || return 0
  starts=$(grep -cxF -- "$start" "$file" || true)
  ends=$(grep -cxF -- "$end" "$file" || true)
  [ "$starts" -eq 0 ] && [ "$ends" -eq 0 ] && return 0
  [ "$starts" -eq 1 ] && [ "$ends" -eq 1 ] ||
    die "$file: region '$region' needs one '$start' line and one '$end' line; found $starts and $ends"
  awk -v start="$start" -v end="$end" -v content="$content" '
    $0 == start {
      print
      n = 0
      while ((getline line < content) > 0) body[++n] = line
      close(content)
      first = 1
      while (first <= n && body[first] ~ /^[ \t]*$/) first++
      last = n
      while (last >= first && body[last] ~ /^[ \t]*$/) last--
      print ""
      for (i = first; i <= last; i++) print body[i]
      if (last >= first) print ""
      inside = 1
      next
    }
    $0 == end {
      if (!inside) exit 3
      inside = 0
    }
    !inside { print }
  ' "$file" >"$out" || die "$file: '$end' comes before '$start'"
  write_if_changed "$out" "$file"
}

# render_template TEMPLATE NAME: TEMPLATE with every `{{name}}` replaced.
render_template() {
  sed -e "s|{{name}}|$2|g" "$1"
}

# strip_front_matter FILE: FILE without a leading `---` ... `---` block.
strip_front_matter() {
  awk '
    NR == 1 && /^---[ \t]*$/ { in_front = 1; next }
    in_front && /^---[ \t]*$/ { in_front = 0; next }
    !in_front { print }
  ' "$1"
}

# hermes_namespace NAME: the skill namespace Hermes gives a package that
# `hermes plugins install` placed, `agent-plugin-<slug>-<first 8 hex of
# sha256(NAME)>`. The documentation gives the form and not the hash:
# https://github.com/NousResearch/hermes-agent/blob/749220ef0007f8d87bd1531f1c24b0fe93816385/website/docs/developer-guide/plugins/index.md
# The source gives both, in `_portable_skill_namespace` and `_portable_slug`:
# https://github.com/NousResearch/hermes-agent/blob/749220ef0007f8d87bd1531f1c24b0fe93816385/hermes_cli/plugins_manifest.py
hermes_namespace() {
  local slug digest
  slug=$(printf '%s' "$1" | tr 'A-Z' 'a-z' | sed -e 's/[^a-z0-9_-]/-/g' -e 's/^[-_]*//' -e 's/[-_]*$//')
  digest=$(printf '%s' "$1" | sha256 | cut -c1-8)
  printf 'agent-plugin-%s-%s\n' "${slug:-plugin}" "$digest"
}

# run_doctoc ARGS...: doctoc from tools/package-lock.json, which pins its
# whole dependency tree, installed into tools/node_modules on first use.
run_doctoc() {
  [ -e tools/node_modules/.bin/doctoc ] || npm ci --prefix tools --no-audit --no-fund >/dev/null
  tools/node_modules/.bin/doctoc --github --notitle "$@" >/dev/null
}

      name,
````
