# Methods cluster (05) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the four reasoning packages (`design-review`, `cognitive-load`,
`toc-thinking`, `triz`) to the spec's manifest, skill and README norms, with their skills
renamed to `red-flags`, `extraneous`, `root-cause` and `contradiction`.

**Architecture:** Each package is changed in two tasks. Task A renames the skill with
`git mv` and fixes its front matter, its reference table and its hand-offs. Task B
rewrites the manifest and the README together, then runs `bash tools/regenerate.sh` (plan 02),
which fills the README's `description` and `install` regions and rewrites the vendor
manifest copy and the catalogue. Plan 02 has already written each package's LICENSE and
the reference TOCs; `git mv` carries the TOCs to the new skill directory. A last task
verifies the whole cluster.

**Tech Stack:** Markdown, JSON, `jq`, `git`, `tools/regenerate.sh` (plan 02, which calls
`npx --yes doctoc@2.2.1`), `tools/check-conformance.py`, `claude plugin validate`
(Claude Code 2.1.278).

Spec: `../specs/2026-09-24-marketplace-quality-design.md` §4.1 (per-manifest part), §5.1,
§5.4, §10. Conventions: `2026-09-25-00-conventions.md` (binding). Review findings
covered: M5, M6, M7, L1, L3, L4 (`../handoff/2026-09-24-marketplace-quality/review/quality-review.md`).

## Split assessment (proposals for the owner, not tasks)

Spec §5.4 asks for every skill to be assessed for size and breadth. Nothing below is
executed before the owner approves it. Names follow the §5.4 rule: one word or one
compound, distinctive without the plugin prefix, never the plugin's name.

### triz: matrix route vs ARIZ — proposed split into `contradiction` and `ariz`

- **Finding.** The skill holds two methods with different triggers. Steps 1–8 are the
  short route: contradiction, ideal final result, separation, parameters, matrix,
  principles. Step 9 is ARIZ-85C, a nine-part algorithm with its own 337-line reference
  that the short route never opens. A third of the front-matter description goes to
  ARIZ, which dilutes the trigger for the common case.
- **Proposal.**
  - `contradiction`: Steps 1–8 as they stand. Step 8's escalation becomes a hand-off to
    the `ariz` skill of the same package. References: `parameters.md`, `principles.md`,
    `matrix.md`, and a `sources.md` holding the sections "The contradiction matrix",
    "The 40 principles", "Separation principles" and the matching "Not read" entries.
  - `ariz`: today's Step 9 as the procedure, with ARIZ parts 1–3 doing their own
    problem statement. References: `ariz-85c.md` and a `sources.md` holding the
    "ARIZ-85C" section and its "Not read" entries. At step 5.3 it names the
    `contradiction` skill for the 40 principles rather than reading the other skill's
    file, because a skill installed alone must not depend on a sibling's directory.
  - Draft description for `ariz`: "Walk a hard software problem through ARIZ-85C,
    Altshuller's nine-part algorithm, after the contradiction matrix gave nothing
    usable. Use when a problem keeps coming back after ordinary fixes, when several
    contradictions feed each other, or when a fix in one place breaks another."
- **Cost.** `sources.md` splits into two files by section, which is a split and not a
  copy. The user who needs ARIZ loads two skills in turn.
- **Recommendation:** split.

### toc-thinking: per tree — no split proposed; a three-way fallback if wanted

- **Finding.** The five tools form one sequence that the TOCICO Dictionary names as one
  (*change question sequence*). Each tool's output is the next one's input: the core
  problem fills the cloud's D, the injection seeds the Future Reality Tree and the
  Prerequisite Tree, and the intermediate objectives order the Transition Tree. Step 1
  routes between entry points. `clr.md` serves three of the five trees. The body is 178
  lines.
- **Per-tree split (five skills: CRT, EC, FRT, PRT, TT).** Rejected. It needs `clr.md`
  in three skills, which is a copy the generator would have to own (a plan 02 change),
  and a sixth routing skill for Step 1.
- **Fallback, if the owner wants a split: by the three questions.**
  - `root-cause`: "What to change?" — Step 1 and the Current Reality Tree. `clr.md`,
    `tools.md` (CRT section), `sources.md`.
  - `dilemma`: "To what to change?" — Evaporating Cloud and Future Reality Tree.
  - `transition`: "How to cause the change?" — Prerequisite Tree and Transition Tree.
  - `clr.md` is needed by all three, so it becomes a generated copy with one source in
    `root-cause`; that is a change to `tools/regenerate.sh` and belongs to plan 02.
- **Recommendation:** keep one skill.
