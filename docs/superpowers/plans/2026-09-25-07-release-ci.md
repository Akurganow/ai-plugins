# Release and CI (cluster 07) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release each changed package straight on `main` with cocogitto, add every external validator to `conformance.yml`, add a model-free install matrix in `integration.yml`, and file the two how-possible issues. Spike 5 is settled by the matrix's first run on this pull request.

**Architecture:** On every push to `main`, `release.yml` runs `cog bump --auto`, which works out each of five packages' next version (howp excluded) from the conventional commits that touched its directory. It writes one version commit and one `<name>--v<version>` tag per package; the workflow pushes them atomically and creates a GitHub release per tag. `conformance.yml` keeps its `check` job and gains three validator jobs plus the rules-file size bound. `integration.yml` is one matrix job (`os × client`) that adds this checkout as a marketplace, installs every package and asserts each skill is listed, plus a per-OS job that downloads and verifies the howp archive. Spike 5 has a local part before the workflows are written (Task 1) and a clean part, the matrix's first run on this pull request (Task 7).

**Tech Stack:** GitHub Actions; cocogitto 7.0.0 (`cargo install --locked` on CI, Homebrew locally); Claude Code 2.1.278 (npm); Codex CLI 0.155.1 (npm); Oh-My-Pi 18.2.8 (bun 1.4.2); Hermes Agent 0.21.5 (its own installer at tag `v2026.9.24`); skills-ref 0.1.0 (from source at a pinned commit); bash, jq, curl, shasum/sha256sum.

- [ ] **Step 1: Run the Hermes and Claude Code validators locally**

`hermes plugins doctor` uses a temporary `HERMES_HOME` (developer guide line 215 at `f97608f`); `validate` reads the path it is given.

```bash
RUN=${RUN:-$(mktemp -d)}
for dir in plugins/*/; do
  d=${dir%/}
  printf '\n$ hermes plugins validate %s\n' "$d";  hermes plugins validate "$d";      echo "exit=$?"
  printf '\n$ hermes plugins doctor %s --ci\n' "$d"; hermes plugins doctor "$d" --ci; echo "exit=$?"
  printf '\n$ claude plugin validate %s\n' "$d";   claude plugin validate "$d";      echo "exit=$?"
done 2>&1 | tee "$RUN/validators-local.txt"
```

Expected: every `claude plugin validate` exits 0, possibly with `Validation passed with warnings`. For Hermes, keep each exit code and the name of each failing check. A check that fails on every package for a reason no package change can fix is "by design" (for example, one that needs `plugin.yaml` or `__init__.py`). A check that fails on one package for a reason in that package goes back to the plan that owns the package.

- [ ] **Step 2: Run the Codex hook control in its own `CODEX_HOME`**

The control is a legacy-format plugin whose `hooks/hooks.json` Codex discovers by default (<https://developers.openai.com/plugins/build/plugins>, "Codex discovers `hooks/hooks.json` by default …"). If its marker never appears in `debug prompt-input`, that command runs no SessionStart hook at all. `CODEX_HOME` keeps the run out of the owner's configuration.

```bash
export CODEX_HOME="$RUN/codex-home"; mkdir -p "$CODEX_HOME"
ctl="$RUN/hook-control"
mkdir -p "$ctl/.claude-plugin" "$ctl/plugins/hook-control/.codex-plugin" "$ctl/plugins/hook-control/hooks"
printf '%s\n' '{"name":"hook-control","owner":{"name":"spike"},"plugins":[{"name":"hook-control","source":"./plugins/hook-control"}]}' > "$ctl/.claude-plugin/marketplace.json"
printf '%s\n' '{"name":"hook-control","version":"0.0.1","description":"Spike 5 control"}' > "$ctl/plugins/hook-control/.codex-plugin/plugin.json"
printf '%s\n' '{"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"echo HOOK-CONTROL-MARKER"}]}]}}' > "$ctl/plugins/hook-control/hooks/hooks.json"
{
  codex plugin marketplace add "$ctl" --json; echo "exit=$?"
  codex plugin add hook-control@hook-control --json; echo "exit=$?"
  codex debug prompt-input > "$RUN/control-no-bypass.json" 2>&1; echo "no-bypass exit=$?"
  codex --dangerously-bypass-hook-trust debug prompt-input > "$RUN/control.json" 2>&1; echo "bypass exit=$?"
  echo "marker count: $(grep -c HOOK-CONTROL-MARKER "$RUN/control.json")"
} 2>&1 | tee "$RUN/codex-control.txt"
unset CODEX_HOME
```

Read the result as one of three:

| Output | Meaning | What Task 5 does |
| :-- | :-- | :-- |
| `bypass exit=0`, marker count ≥ 1 | `debug prompt-input` runs SessionStart hooks | keeps the hook step as written, allowed to fail |
| `bypass exit=0`, marker count 0 | it runs no SessionStart hook | replaces the hook step with the "not run" notice (lead's decision) |
| `bypass exit` non-zero, and the output asks for a login | not answered locally | keeps the hook step as written; Task 7 reads the answer from the first run |

A flag error (`unexpected argument`) on the top-level `--dangerously-bypass-hook-trust` is a fourth case. Record it, then retry with `codex debug prompt-input -c` followed by the equivalent config key if `codex --help` names one. If it names none, treat the case as "not answered locally".

### Task 3: `release.yml`, and the seed tags

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `cog.toml` (Task 2); `$RUN/clone` after Task 2's rehearsal.
- Produces: on each push to `main`, a version commit and tags `<name>--v<version>` pushed to `main`, and one GitHub release per new tag; before merge, five seed tags on `232aaba`.

The loop guard is GitHub's rule, not a message marker: "When you use the repository's `GITHUB_TOKEN` to perform tasks, events triggered by the `GITHUB_TOKEN` will not create a new workflow run … if a workflow run pushes code using the repository's `GITHUB_TOKEN`, a new workflow will not run even when the repository contains a workflow configured to run when `push` events occur." Source: doc, [`data/reusables/actions/actions-do-not-trigger-workflows.md`](https://github.com/github/docs/blob/75ea7dd097a5564f27364a5b70eaa1979106eabd/data/reusables/actions/actions-do-not-trigger-workflows.md), shown at <https://docs.github.com/en/actions/concepts/security/github_token>. The same rule means `conformance.yml` does not run on the version commit; the spec accepts that because the commit changes only what the hook and cocogitto write. Task 7 Step 8 runs the check locally on it once.

`main` has no classic branch protection. Its one active ruleset, `main` (id 21664827, target `~DEFAULT_BRANCH`), applies only `deletion` and `non_fast_forward`, with repository admins as bypass actors. Read with `gh api repos/Akurganow/ai-plugins/rulesets/21664827` on 2026-09-25. A fast-forward push of the version commit and its tags with `GITHUB_TOKEN` is therefore allowed, and `contents: write` is the only scope needed ("`contents: write` allows the action to create a release", doc, [`github-token-scope-descriptions.md`](https://github.com/github/docs/blob/75ea7dd097a5564f27364a5b70eaa1979106eabd/data/reusables/actions/github-token-scope-descriptions.md)). No personal token is used.

The bot identity is the one `actions/checkout` documents for pushing with the built-in token ([`README.md`](https://github.com/actions/checkout/blob/f548e57e544e1ff5a4c46bf1e1b8685f8e4a348a/README.md) lines 332–349). `gh release create --verify-tag` aborts when the tag is not already on the remote (<https://cli.github.com/manual/gh_release_create>). The push therefore happens first, as one atomic push of the commit and its tags.

- [ ] **Step 3: Write `.github/workflows/release.yml`**

```yaml
name: release

# Releases each package whose files changed since its last tag, straight on
# main, with cocogitto (https://docs.cocogitto.io/guide/monorepo). cog.toml
# names the packages and writes the version into both manifests.
#
# Loop guard: a push made with GITHUB_TOKEN starts no new workflow run
# (https://docs.github.com/en/actions/concepts/security/github_token), so the
# version commit and its tags do not run this workflow again.
# The "main" ruleset forbids only deletion and non-fast-forward pushes, so the
# fast-forward push below is allowed.
on:
  push:
    branches: [main]

# One release at a time; the next run starts from the main this one pushed.
concurrency:
  group: release
  cancel-in-progress: false

permissions:
  contents: read

jobs:
  release:
    runs-on: ubuntu-latest
    # Pushing the commit and the tags and creating releases need contents: write.
    permissions:
      contents: write
    steps:
      # Pinned to a commit sha; the comment records the release. ref: main
      # takes the newest main; fetch-depth: 0 brings the history and the tags.
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0
        with:
          ref: main
          fetch-depth: 0

      # cocogitto documents cargo install, pinned with --version
      # (website/guide/migrations.md). ubuntu-latest carries cargo.
      - name: Install cocogitto
        run: |
          cargo install --locked cocogitto --version 7.0.0
          cog --version

      - name: Bump every package with releasable commits
        id: bump
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          before=$(git rev-parse HEAD)
          cog bump --auto
          if [ "$(git rev-parse HEAD)" = "$before" ]; then
            echo "No package has a releasable commit."
            echo "released=false" >> "$GITHUB_OUTPUT"
            exit 0
          fi
          git tag --points-at HEAD | grep -e '--v' > "$RUNNER_TEMP/new-tags"
          echo "New tags:"; cat "$RUNNER_TEMP/new-tags"
          echo "released=true" >> "$GITHUB_OUTPUT"

      - name: Push the version commit and its tags
        if: steps.bump.outputs.released == 'true'
        run: git push --atomic origin HEAD:main $(sed 's#^#refs/tags/#' "$RUNNER_TEMP/new-tags")

      # The notes are the new section of the package's CHANGELOG.md, which
      # cocogitto heads "## <tag> - <date>".
      - name: Create one GitHub release per new tag
        if: steps.bump.outputs.released == 'true'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          while read -r tag; do
            name=${tag%--v*}
            notes="$RUNNER_TEMP/$tag.md"
            awk -v head="## $tag " 'index($0, head) == 1 { p = 1; next } p && (/^- - -$/ || /^## /) { exit } p' \
              "plugins/$name/CHANGELOG.md" > "$notes"
            gh release create "$tag" --verify-tag --title "$tag" --notes-file "$notes"
          done < "$RUNNER_TEMP/new-tags"
```
