Write `$S/sentences.awk` with exactly this content:

~~~awk
# Prints every sentence longer than 25 words as FILE:LINE: words: text.
# Code blocks, block quotes, inline code, quoted text and link targets are
# exempt, as prose-discipline's exemptions say. Table cells, headings and
# list items are separate units.
function flush() { if (buf != "") check(buf, start); buf = ""; start = 0 }
function check(s, line,    n, i, parts, w, t, k, words) {
  gsub(/\]\([^)]*\)/, "]", s)
  gsub(/<https?:[^>]*>/, " URL ", s)
  gsub(/`[^`]*`/, " CODE ", s)
  gsub(/"[^"]*"/, " QUOTE ", s)
  gsub(/https?:[^ )]*/, " URL ", s)
  n = split(s, parts, /[.!?][)]?([ \t]|$)/)
  for (i = 1; i <= n; i++) {
    words = 0
    k = split(parts[i], w, /[ \t]+/)
    for (t = 1; t <= k; t++) if (w[t] ~ /[A-Za-z0-9]/) words++
    if (words > 25) printf "%s:%d: %d words: %s\n", FILENAME, line, words, parts[i]
  }
}
FNR == 1 { flush(); code = 0 }
/^[ \t]*(```|~~~)/ { flush(); code = !code; next }
code { next }
/^[ \t]*$/ { flush(); next }
/^>/ { flush(); next }
/^#/ { flush(); check($0, FNR); next }
/^\|/ { flush(); if ($0 ~ /^\|[ :|-]+\|[ \t]*$/) next; nc = split($0, cells, "|"); for (c = 1; c <= nc; c++) check(cells[c], FNR); next }
/^[ \t]*([-*]|[0-9]+\.)[ \t]/ { flush() }
{ if (start == 0) start = FNR; buf = buf " " $0 }
END { flush() }
~~~

Write `$S/check-quotes.sh` with exactly this content:

~~~bash
#!/usr/bin/env bash
# Fetches every cited page or file and checks the quoted phrase is still there.
# Each line of quotes.txt is URL|phrase. Whitespace is compared collapsed, and
# HTML tags are ignored, so a phrase wrapped across lines still matches.
set -uo pipefail
S=/private/tmp/claude-501/-Users-akurganow-Projects-ai-plugins/aa53b02e-f388-4b09-bc13-baf4eb5c52bb/scratchpad/closing
fail=0
while IFS='|' read -r url phrase; do
  [ -n "$url" ] || continue
  raw=$(curl -sL --max-time 30 "$url")
  plain=$(printf '%s' "$raw" | tr -s '[:space:]' ' ')
  untagged=$(printf '%s' "$raw" | sed 's/<[^>]*>//g' | tr -s '[:space:]' ' ')
  want=$(printf '%s' "$phrase" | tr -s '[:space:]' ' ')
  case "$plain$untagged" in
    *"$want"*) ;;
    *) echo "MISSING: $url :: $phrase"; fail=1 ;;
  esac
  sleep 0.3
done < "$S/quotes.txt"
echo "fail=$fail"
exit "$fail"
~~~

## Claude Code

Documentation pages below were read on 2026-09-25.

### Manifest and fetch

- The documented manifest location is `.claude-plugin/plugin.json` under the plugin root.
  (documentation: [Plugin manifest reference, Manifest file](https://code.claude.com/docs/en/plugins/manifest-reference#manifest-file))
- A manifest that is not valid JSON fails with `Plugin <name> has a corrupt manifest file`.
  (documentation: [Troubleshoot plugins](https://code.claude.com/docs/en/plugins/troubleshooting#plugin-has-a-corrupt-manifest-file-or-has-an-invalid-manifest-file))
- Claude Code strips an unrecognized top-level manifest field, and the plugin loads.
  `claude plugin validate` reports the field as a warning.
  (documentation: [Plugin manifest reference, Unrecognized fields](https://code.claude.com/docs/en/plugins/manifest-reference#unrecognized-fields))
- Claude Code clones a marketplace hosted in git onto the user's machine.
  (documentation: [Host and maintain a marketplace](https://code.claude.com/docs/en/plugins/host-marketplace))
- A plugin starts enabled unless `defaultEnabled` is `false`.
  (documentation: [Plugin manifest reference, defaultEnabled](https://code.claude.com/docs/en/plugins/manifest-reference#defaultenabled))
- Users stay on their cached copy until the `version` string changes.
  (documentation: [Host and maintain a marketplace, Release a new version](https://code.claude.com/docs/en/plugins/host-marketplace#release-a-new-version))
- Release tags take the form `<plugin-name>--v<version>`.
  (documentation: [Plugin dependencies, Create a release tag](https://code.claude.com/docs/en/plugins/dependencies#create-a-release-tag))

### Skills

- Claude Code namespaces a plugin skill by its plugin: `skills/review/` in `my-plugin` is `/my-plugin:review`.
  The bare `/review` also works unless another command already uses that name.
  (documentation: [Skills, How a skill gets its command name](https://code.claude.com/docs/en/skills#how-a-skill-gets-its-command-name))
- Skill descriptions sit in context, and a skill's full content loads only when it is invoked.
  (documentation: [Skills, Skill content lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle))

### Always-on instructions

- A `CLAUDE.md` at the plugin root is not loaded as context.
  The page directs instructions into a skill.
  (documentation: [Plugin manifest reference, Standard layout](https://code.claude.com/docs/en/plugins/manifest-reference#standard-layout))
- The component list names no `rules/` directory.
  (documentation: [Add components to a plugin](https://code.claude.com/docs/en/plugins/components#add-each-kind-of-component))
- For `SessionStart`, Claude Code adds plain-text stdout to the context.
  Stdout that starts with `{` and ends with `}` is parsed as JSON instead.
  (documentation: [Hooks, Exit code 0](https://code.claude.com/docs/en/hooks#exit-code-0))
- `SessionStart` matchers are `startup`, `resume`, `clear`, `compact` and `fork`.
  (documentation: [Hooks, SessionStart](https://code.claude.com/docs/en/hooks#sessionstart))
- After compaction, `SessionStart` hooks matching `compact` run, and their output joins the compacted context.
  (documentation: [Context window, What survives compaction](https://code.claude.com/docs/en/context-window#what-survives-compaction))
- Plain stdout and `additionalContext` are capped at 10,000 characters.
  Longer text reaches Claude as a file path and a preview.
  (documentation: [Hooks, JSON output](https://code.claude.com/docs/en/hooks#json-output))
- `SubagentStart` adds its `additionalContext` to a subagent's context before the first prompt.
  The page documents no plain-stdout route for this event.
  (documentation: [Hooks, SubagentStart](https://code.claude.com/docs/en/hooks#subagentstart))
- A command hook without `args` runs in shell form: `sh -c` on macOS and Linux, Git Bash on Windows.
  With `args`, it runs in exec form, without a shell.
  (documentation: [Hooks, Exec form and shell form](https://code.claude.com/docs/en/hooks#exec-form-and-shell-form))

# 1. Every copy is generated from one source

## Status

Accepted, 2026-09-24.

## Context

Clients read the same facts from different files.
Claude Code documents one manifest location, `.claude-plugin/plugin.json`.
Codex takes a plugin's category from the marketplace entry, and shows `Other` without one.
Hermes loads nothing from a package but its manifest, its skills and `mcp.json`.
[How the four clients load a package](../clients.md) cites each of these facts.

So the same text has to exist in several files.
The catalogue repeats each manifest's description and category.
Every package README carries the same four install blocks, and every package needs its own `LICENSE`.
A copy kept by hand drifts from its source, and nothing notices until a reader does.

## Decision

`plugins/<name>/plugin.json` is the only source of package metadata.
The category sits under `extensions["io.github.akurganow.ai-plugins"]`, which no client reads.
It reaches clients through the catalogue.

`tools/regenerate.sh` writes every copy.
Its steps are the list of copies, and it calls ready-made tools in a fixed order.
Each generated region inside a hand-written file sits between two HTML comment markers.

CI runs the script and then `git diff --exit-code`.
CI checks the copies and never writes them.

## Consequences

- A contributor edits the source and runs one command.
  When a copy differs, the CI failure names that command.
- The next run overwrites a hand edit between markers.
- Every generated change shows up in the pull request as a diff.
- The script is one more file to maintain, beside tools that each do one job.

# 2. The vendor manifest is a copy, not a symlink

## Status

Accepted, 2026-09-25.

## Context

Claude Code documents one manifest location, `.claude-plugin/plugin.json`.
A file there that is not JSON fails the install as a corrupt manifest.
Codex, Hermes and Oh-My-Pi's `agent-plugins` provider read the root `plugin.json` instead.
Every client fetches a marketplace with `git clone` on the user's machine.
[How the four clients load a package](../clients.md) cites each of these facts.

Git checks a symlink out as a plain file holding the link text when `core.symlinks` is false.
(documentation: [git manual, `core.symlinks`, v2.51.0](https://github.com/git/git/blob/c44beea485f0f2feaf460e2ac87fdd5608d63cf0/Documentation/config/core.adoc#L237-L246))

Git for Windows disables symlink support by default.
(documentation: [Symbolic links in Git for Windows](https://gitforwindows.org/symbolic-links), read 2026-09-25)

Its installer enables symlinks only with Developer Mode, or when a test link succeeds for the installing user.
(source: [`install.iss` L1342–L1369](https://github.com/git-for-windows/build-extra/blob/c8241c75c7c06d6db94ed6a8dd9b8ca76d1ed842/installer/install.iss#L1342-L1369),
[L2459–L2467](https://github.com/git-for-windows/build-extra/blob/c8241c75c7c06d6db94ed6a8dd9b8ca76d1ed842/installer/install.iss#L2459-L2467))

So a default Windows checkout turns a symlinked vendor manifest into a text file.
Claude Code then fails to load the package.

GitHub's Windows runner image installs Git with symlinks enabled.
(source: [`Install-Git.ps1` L27–L37](https://github.com/actions/runner-images/blob/ebade26c60adcb867918b31c8f8caa37343a3d39/images/windows/scripts/build/Install-Git.ps1#L27-L37))

A CI job on that image cannot reproduce a user's default checkout.

Agent Plugins 1.0.0 §5.1 says no other file can "replace, supplement, or override the core fields in root `plugin.json`".
(documentation: [Agent Plugins specification §5.1](https://github.com/agentplugins/agent-plugins-spec/blob/ff8ab5e392cc87bd88d87c060815a87490e51003/spec/1.0.0.md#L133-L137))

A byte-identical copy overrides nothing.

## Decision

`plugins/<name>/.claude-plugin/plugin.json` is a regular file, byte-identical to the root `plugin.json`.
`tools/regenerate.sh` writes it, and the conformance check compares the two files byte for byte.

## Consequences

- A Windows user installs with Git's defaults, and Claude Code finds a valid manifest.
- Each package carries its manifest twice.
  The generator and the check keep the two equal.
- The Windows integration job proves loading on the runner image only.
  The copy, not that job, protects a user's checkout.

# 3. Skill names stand without the plugin prefix

## Status

Accepted, 2026-09-24.

Claude Code, Codex and Hermes prefix a plugin skill with a plugin namespace.

## Status

Accepted, 2026-09-24.

## Context

`prose-discipline` ships a writing standard that should be active in every session, without the user invoking it.
Each client offers a different documented route for standing instructions:

- Codex: the same hooks, declared under `extensions.com.openai`, after the user trusts them.
- Oh-My-Pi: a plugin `rules/` file with `alwaysApply: true`.

That keeps the hook's text under Codex's default spill threshold.

- One edit to the rules file reaches all four clients.
- For `SessionStart`, the script prints a heading first, since Claude Code parses `{`-first output as JSON.
- In Claude Code and Oh-My-Pi, invoking the skill puts the rules in context a second time.
  That cost is accepted.
- In Hermes, the user adds one config entry, and nothing else in Hermes loads the rules.
- In Codex, the user trusts the hook once, and again after each change to it.

# 5. The standard is recommended, not enforced

## Status

Accepted, 2026-09-24.

## Context

Clients offer ways to force a writing standard, not only state it.

Claude Code's `Stop` hook can return `"decision": "block"` and keep the turn going.
(documentation: [Hooks, Stop decision control](https://code.claude.com/docs/en/hooks#stop-decision-control), read 2026-09-25)

A `PreToolUse` hook can deny a file write.
(documentation: [Hooks, PreToolUse decision control](https://code.claude.com/docs/en/hooks#pretooluse-decision-control), read 2026-09-25)

A `UserPromptSubmit` hook can add context on every prompt.
(documentation: [Hooks, UserPromptSubmit](https://code.claude.com/docs/en/hooks#userpromptsubmit), read 2026-09-25)

In Oh-My-Pi, a TTSR rule aborts a response on a match and retries it.
[How the four clients load a package](../clients.md#oh-my-pi) cites that fact.

## Decision

`prose-discipline` states the standard and does not enforce it.
It ships no blocking hook, no per-prompt reminder and no TTSR rule file.
The standard enters each context once, and again only where the client dropped it, as after compaction.

A gate that blocks the agent does harm.
Repeating text already in context is noise.

## Consequences

- Compliance rests with the model.
  Nothing in the package checks the output.
- The package adds its text once per context, not once per turn.

# 10. howp archives are signed where they are built

## Status

Accepted, 2026-09-24.

## Context

`howp` downloads and runs `hp`, a binary built from sources that are not public.
The skill checks each archive's SHA-256 against [`binaries.json`](../../plugins/howp/binaries.json).
A digest proves the archive is the one recorded, not who built it.

## Decision

The release job that builds `hp` signs `SHA256SUMS` with Sigstore cosign keyless signing.
This repository's CI verifies that signature against the release workflow's identity.
The skill keeps its SHA-256 check and does not call cosign.

Two alternatives lost.
GitHub build attestations from a private repository verify only with access to that repository.
cosign inside the skill needs cosign on every user's machine.

## Consequences

- The signing step belongs to the repository that builds the binaries.
- Until that repository signs a release, CI checks the release's SHA-256 only.
