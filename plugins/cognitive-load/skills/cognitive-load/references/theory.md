# Cognitive load theory, as far as it was read

What the theory says, what it no longer says, and where it stops applying
to code. `sources.md` says where each statement was read. Most primary
papers were not reachable whole, and each quotation below says whether it
comes from a paper's abstract, from a full text, or from a secondary
source.

## Origin

John Sweller, "Cognitive Load During Problem Solving: Effects on
Learning", *Cognitive Science* 12(2), 1988. Its abstract, read from a
public mirror: conventional problem solving "in the form of means-ends
analysis requires a relatively large amount of cognitive processing
capacity which is consequently unavailable for schema acquisition". The
abstract does not contain the words intrinsic, extraneous or germane. The
body was not opened. The three terms are attributed to later papers,
below.

- **Intrinsic** and **extraneous** load. Wikipedia's article says the
  term intrinsic "was first used in the early 1990s by Chandler and
  Sweller", citing "Cognitive Load Theory and the Format of
  Instruction", *Cognition and Instruction* 8(4), 1991, and credits the
  same authors with extraneous load in a sentence tagged "citation
  needed". The article's own definitions, not the paper's: intrinsic is
  "the inherent level of difficulty associated with a specific
  instructional topic". Extraneous "is generated by the manner in which
  information is presented to learners and is under the control of
  instructional designers". Neither the 1991 paper nor Sweller 1994, to
  which intrinsic load is also often attributed, was opened.
- **Germane** load. Which paper introduced it was not verified. A search
  engine's summary names Sweller, van Merriënboer and Paas, "Cognitive
  Architecture and Instructional Design", *Educational Psychology
  Review* 10, 1998. The abstract of that paper, read from a mirror,
  describes "a limited capacity working memory" and "an effectively
  unlimited long-term memory, holding schemas that vary in their degree
  of automation", and names none of the three kinds of load. No source read here states
  the additive model in which the three loads sum to a total.

## What changed

Sweller, "Element Interactivity and Intrinsic, Extraneous, and Germane
Cognitive Load", *Educational Psychology Review* 22, 2010. Its abstract,
read from a mirror: "germane cognitive load can be defined in terms of
intrinsic cognitive load, thus also associating germane cognitive load
with element interactivity." Sweller, van Merriënboer and Paas, 2019, in
the same journal, volume 31: its abstract was read from a mirror. One
sentence of its body was read only as a third party quoted it, that the
authors now assume "germane cognitive load redistributes working memory
resources from extraneous activities to activities directly relevant to
learning". Kalyuga, 2011, in the same journal, volume 23, argues the
third type is redundant. It was not opened, and that summary is a search
engine's. Wikipedia's article records a related doubt in its lead: "the
additivity of these types of cognitive load has been investigated and
questioned."

So this skill works with two loads. The 2010 abstract draws the line
between them: "whether element interactivity is essential to the task at
hand or whether it is a function of instructional procedures." For code,
read "instructional procedures" as the structure and presentation of the
code. The skill treats "germane" as the name for the working memory a
reader devotes to the elements the task needs, which is how that abstract
ties germane load to intrinsic load, and not as a third pile. It gives
nobody an instruction to protect germane load. No source read here gives
one. That germane load is not a separate type is Sweller's position as
read in two abstracts and one third-hand quotation. Kalyuga's argument is
known here only through a summary.

## Element interactivity

The 2010 abstract calls element interactivity "the basic, defining
mechanism of intrinsic cognitive load" and adds that "element
interactivity underlies extraneous cognitive load as well". In this
skill's words, not the abstract's: the number of elements that must be
related to one another at the same time to do the task, counted in units
the reader already holds. It is a construct, not an effect. It is the
quantity Step 3 counts, before sorting each element as essential to the
task or added by the structure.

## Capacity

Cowan, "The magical number 4 in short-term memory: A reconsideration of
mental storage capacity", *Behavioral and Brain Sciences* 24, 2001. Its
abstract, read from a mirror: Miller's seven "was meant more as a rough
estimate and a rhetorical device than as a real capacity limit". The
limit is observed under four conditions, among them "when information
overload limits chunks to individual stimulus items" and "when other
steps are taken specifically to block the recoding of stimulus items into
larger chunks". "A single, central capacity limit averaging about four
chunks is implicated". Reading code blocks nothing, so the four is not a
budget to count code elements against. This skill states no element
budget.

Miller, "The Magical Number Seven, Plus or Minus Two", *Psychological
Review* 63, 1956, read whole from a public mirror. On chunking: "Since the
memory span is a fixed number of chunks, we can increase the number of
bits of information that it contains simply by building larger and larger
chunks, each chunk containing more information than before." On the
number: "I suspect that it is only a pernicious, Pythagorean coincidence."

What this means for code, as this skill's inference and not a finding on
code. The 2019 abstract states the principle: novel information is
"processed by a capacity and duration limited working memory", and "Once
information is stored in long-term memory, the capacity and duration
limits of working memory disappear". Miller's chunking sentence is the
same point in 1956 terms. So the limit binds on what the reader does not
already know. A pattern held as one schema costs one chunk, and the same
code costs a newcomer several. The one study on code read here adds a
caution: experience "increases performance in most cases, but may hurt
performance significantly when underlying assumptions about related code
statements are violated" (Hansen and others, 2013, in `measures.md`).
That is why the author is the wrong judge of the load, and why the skill
checks with newcomers.

## The effects

Cognitive load theory's findings are stated as effects: a change in
instructional material that changed learning. Wikipedia's article names
those demonstrated in the 1990s: "the completion-problem effect; modality
effect; split-attention effect; worked-example effect; and expertise
reversal effect". The catalogue is larger. A search engine's summary of
Sweller, Ayres and Kalyuga's 2011 book lists about fifteen, among them
goal-free, isolated elements, variability, redundancy, self-explanation,
imagination and transient information. The book was not opened.

Three were read in their Wikipedia articles:

- **Worked-example effect.** "Improved learning observed when worked
  examples are used as part of instruction, compared to other
  instructional techniques such as problem-solving." The article says
  worked examples "improve learning by reducing cognitive load during
  skill acquisition" and that studying them "loses its effectiveness with
  increasing expertise". For code, by analogy only: a solved example
  beside an API should spare a first-time caller the search that reading
  a reference alone demands.
- **Split-attention effect.** "It is apparent when the same modality (e.g.
  visual) is used for various types of information within the same
  display. Users must split their attention between the materials, for
  example, an image and text, to understand the information being
  conveyed." For code: the fact a reader needs sits in another file, a
  wiki page or a configuration, and must be held while reading this one.
  Text plus a separate diagram, both visual and both needed, is this
  effect. The modality effect is a different one. The 1998 abstract's
  working memory "includes partially independent subcomponents to deal
  with auditory/verbal material and visual/2- or 3-dimensional
  information", and that effect concerns using both channels. Its own
  definition was not read here.
- **Expertise reversal effect.** "The reversal of the effectiveness of
  instructional techniques on learners with differing levels of prior
  knowledge." Instructional techniques "that assist learners to create
  long term memory schema are more effective for novices or low-knowledge
  individuals". For experts, "reduced guidance often results in better
  performance than well-guided instruction". For code, by analogy: a
  comment that walks a newcomer through a loop can slow an expert down,
  because for experts such guidance "can result in the processing of
  redundant information and increased cognitive load". Both readers
  exist.

Worked examples and the split-attention effect are, in the sources read,
about extraneous load. For intrinsic load the article's own suggestion is
to divide it: "many schemas may be broken into individual 'subschemas'
and taught in isolation, to be later brought back together and described
as a combined whole."

Every effect was established on instructional material for learners. Its
application to a code base is an analogy until a study on code shows it.
`measures.md` carries the studies on code that were read.

## Where the theory stops

Cognitive load theory is a theory of learning. A developer reading code is
not always learning it. In this skill's reading, they are often trying to
complete a task with the least understanding that suffices. No study of
that was read here. The practitioner text this skill draws on says of its
own use of the term: "We are going to use 'cognitive load' in an informal
sense; sometimes it lines up with the specific scientific concept of
Cognitive Load, but we don't know enough about where it does and doesn't
match" (the essay's introduction, in the copy `sources.md` names). This skill keeps
that distinction. Where it says "load", it means what a reader must keep
in mind to do a task, and it says which sense it is in when the
difference matters.
